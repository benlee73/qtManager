# QT Manager 프로젝트 역사 기록

> 이 문서는 QT Manager의 과거 결정, 단계별 진행 기록 및 변경 이력을 보관하는
> 비규범적(archival) 문서다.
>
> 현재 제품의 요구사항과 업무 규칙은 항상 [PROJECT_SPEC.md](../PROJECT_SPEC.md)를
> 기준으로 한다. 두 문서가 다르면 PROJECT_SPEC.md의 현재 기준을 우선하고,
> 이 문서는 왜 그런 기준이 만들어졌는지 추적할 때 참고한다.

## 1. 기록 관리 원칙

- 과거 기록은 삭제하지 않고 요약해 보존한다.
- 현재 기준을 바꾼 결정은 PROJECT_SPEC.md의 요구사항·규칙·ADR 요약에도 반영한다.
- 폐기되거나 대체된 결정에는 상태를 표시하고 새 기준을 별도로 기록한다.
- 이 문서와 저장소에 실제 이름, 전화번호, 계좌번호, 운영 XLSX 행을 넣지 않는다.
- 변경 이력의 요약은 개인정보를 포함하지 않는 업무 단위로 작성한다.

## 2. 단계별 진행 기록

### 2026-08-07

- 현장 배부의 만료 신청자 행에서 `구독 갱신`을 일반 배부 버튼처럼 비활성화하거나
  배부 경로로 보내던 결함을 수정했다. 이제 버튼은 활성 상태로 표시되고 해당
  신청자 관리 상세와 `구독 추가·갱신` 대화상자를 바로 연다. 만료 호의 일반 배부
  차단 규칙은 그대로 유지하며, 단위 테스트와 Tauri E2E 회귀 검증을 추가했다.
- 신청자 관리에서 마우스로 선택한 행도 키보드 포커스를 유지해 `ArrowUp`·
  `ArrowDown`이 목록 스크롤 대신 신청자 이동으로 동작하도록 보정했다. 첫 행의
  위 방향키 복귀와 관리 화면 `/` 검색 포커스 회귀 E2E를 추가했다.
- 신청자 전환 중 이전 상세를 유지해 빈 상태가 잠깐 나타나는 깜빡임을 제거하고,
  새 상세 로딩 실패 때만 빈 상태로 전환하도록 관리 로더 테스트를 갱신했다.
- 신청자 상세 하단의 보관·삭제 동작을 하나의 액션 그룹으로 재배치했다. 보관은
  중립적인 되돌릴 수 있는 동작으로, 삭제는 저채도 빨간 파괴적 동작으로 구분했다.
- 현장 배부 상단 통계의 호 제목과의 간격·셀 내부 여백을 조정해 네 값이 같은
  기준선에서 읽히도록 했다.

### Phase 0 — 요구사항 확정과 기술 검증 (2026-07-24, 완료)

- Node.js 24 LTS, pnpm 11, Rust 1.97.1과 Tauri 2, React, SQLite, XLSX,
  Vitest, Rust 테스트, WebdriverIO Tauri E2E 조합을 검증했다.
- Domain → Application/Ports → Infrastructure → Desktop 의존성 방향을 갖는
  Rust workspace를 만들었다.
- 개인정보가 없는 2026년 월별 XLSX fixture, SQLite 저장, XLSX v1 왕복 및
  실제 macOS 데스크톱 수직 흐름을 검증했다.
- macOS와 Windows에서 같은 just 명령을 실행하는 CI를 구성하고 XLSX v1의
  필수 시트·관계·값 표현을 확정했다.

### Phase 1 — 핵심 도메인과 로컬 저장 (2026-07-24, 완료)

- QT 호, 연속 6개 호 구독, 연도 경계, 예정·유효·만료·확인 필요 상태와
  겹침 경고를 구현했다.
- 1권·여러 권의 미배부·일부·완료·초과 상태, 기본 전체 배부, 일부 배부,
  중복 방지 및 취소 이력을 도메인 테스트로 확정했다.
- SQLite 스키마 v2와 Person, Subscription, Distribution, OneTimePurchase,
  기록·로그·복원 관련 테이블 및 트랜잭션 마이그레이션을 검증했다.
- 저장소 포트·어댑터, 원자적 저장·롤백, 재실행 복원 및 핵심 Tauri E2E를
  완료했다.

### Phase 2 — 현장 배부 MVP (2026-07-24, 완료)

- 빈 검색어의 미완료 목록, 이름·부분 이름·또래·전화번호 검색, 호 이동,
  인원·권수 통계 및 QT 호 기준 자격 판정을 구현했다.
- 여러 권 기본 전체 배부, 일부 배부, 배부 취소·되돌리기, 담당자 이력,
  간이 등록, 확인할 일·고정 메모 전신 기록, 부수적인 현장 개별 구매와
  취소를 검증했다.
- 운영 DB와 격리된 테스트 캐시를 사용한 실제 Tauri E2E와 SQLite 재실행
  통합 테스트를 완료했다.

### Phase 3 — 신청과 관리 (2026-07-26, 완료)

- QT 신청자 직접 등록·수정·보관·복원, 구독 추가·갱신·기간 겹침 경고,
  구독·배부 이력 상세를 구현했다.
- 제출 시각·입금 열 유무, 뒤쪽 빈 셀, 헤더 별칭 및 수동 매핑을 허용하는
  Google 응답 TSV 파서와 행별 미리보기·오류 보존·중복 응답 차단을 완료했다.
- 신청자·구독·가져오기 배치·업무 이력을 한 트랜잭션으로 저장하고 실제
  데스크톱 E2E와 SQLite 재실행 통합 테스트를 완료했다.
- 오프라인 도움말과 빠른 시작을 제공했다.

### Phase 3.5 — UI·정보구조 정비 (2026-07-27 ~ 2026-08-04, 완료)

- 라이트·다크 테마 저장, QT 로고, 76px 좌측 내비게이션 레일, 조밀한 표,
  우측 확인할 일·고정 메모, 균등한 4칸 통계를 적용했다.
- 1000×720 시작·900×640 최소 크기 조절 창, 전체 스크롤 금지와 영역별
  내부 스크롤, 전체 전화번호의 상세 접근을 정비했다.
- 기록 용어를 확인할 일·고정 메모·신청자 메모로 구분하고 신청자 연결,
  체크리스트 상태, 보관함, 복원, 삭제 확인 및 되돌리기·다시 실행을 추가했다.
- 신청자 관리의 간결한 목록, 상세 스크롤, 직접 메모·연결 확인할 일 입력,
  구독 시작·끝 호 표시, 도움말 카드·동기화 목차를 반영했다.
- 다크·라이트 시각 캡처, 단위·통합 테스트와 macOS Tauri E2E를 갱신했다.
- GitHub Actions 호스팅 macOS·Windows 릴리스 후보 검증은 완료했지만, Windows
  실제 장치 검증은 아직 완료로 표시하지 않는다.

### Phase 4 — 인수인계 (2026-07-27, 완료)

- XLSX 형식 v2의 안내·설정·신청자·구독·배부·개별구매·메모·변경이력·호별현황
  9개 시트를 구현하고, v1의 기록 시트는 읽기 호환으로 남겼다.
- 현재 상태 교체·병합, 엔터티별 최신 수정 시각 충돌 처리, 고유 이력 합집합,
  동일인 후보 수동 해결 및 가져오기 전 복원 지점을 검증했다.
- 앱 재시작 뒤 복원, 개인정보 주의 안내, 애플리케이션 로그·업무 이력,
  네이티브 파일 선택과 왕복 테스트를 완료했다.

### 메모 통합 정비 — 2026-08-05, 구현 완료

- 확인할 일·고정 메모·신청자 메모를 사용자-facing `메모` 하나로 통합하기로
  결정했다.
- 새 메모는 선택적 신청자 연결과 `활성·보관` 2단계 상태만 사용하며 체크박스와
  고정 상태는 제거한다. 보관은 완료 또는 당분간 숨김을 뜻하고 보관함에서
  복원할 수 있다.
- SQLite schema v4와 XLSX format v2에서 `memos`/`메모`를 기준으로 삼고, 기존
  세 기록과 XLSX v1은 원자적 호환 마이그레이션으로 보존한다.
- 상세 창의 본문 클릭 편집, 변경 시에만 저장 표시, 카드의 전문 보기·보관·삭제
  버튼 제거, 보관함의 메모 전용 표시와 도움말 갱신을 구현했다.
- SQLite·XLSX 호환 마이그레이션, 배부 화면·신청자 상세·수정창의 생성 경로별
  연결, 활성·보관·복원·삭제 흐름을 단위·통합·macOS Tauri E2E로 검증했다.

### 2026-08-05 후속 UI·상태 보정 — 구현 완료

- 메모 상세 창의 본문 정렬·높이·글자 크기를 조정하고, 보관함에서 복원과 삭제를
  모두 제공했다. 신청자 수정창에서 메모를 만들거나 편집하면 같은 창의 목록에
  즉시 반영되도록 했다.
- 현장 배부 행 메뉴의 `상세 정보 보기`를 신청자 관리 상세로 연결하고, 두 화면을
  오갈 때 목록 스크롤·선택·상세 스크롤을 유지했다.
- 대상·완료·남음·배부 통계를 가운데 정렬하고 신청자 관리 상단 여백을 줄였으며,
  또래가 없는 활성 신청자도 `정보 보완 필요` 집계와 상태 표시에 포함했다.
- 관련 단위·통합·macOS Tauri E2E를 갱신했다. 로컬 E2E는 10개 통과·2개 선택
  제외로 확인했으며 GitHub Actions는 사용자가 요청하기 전까지 실행하지 않는다.

### 2026-08-05 도움말 보조 글자 균형 보정

- `단축키 > 자주 쓰는 동작`의 키 설명과 `앱 정보와 문제 보고 > 지원 정보`의
  버전·경로 값을 공통 보조 글자 크기로 한 단계 줄여 본문 제목과 위계를 맞췄다.
- 데이터·로그 경로는 전체 값, 줄바꿈, 툴팁을 그대로 유지해 작은 글자에서도
  지원 정보가 잘리지 않도록 했다.

### 2026-08-05 목록 여백 보정

- 화면 크기와 글자 크기 토큰은 유지하면서 신청자 행의 최소 높이와 세로 여백을
  소폭 늘리고, 우측 메모 카드의 내부·카드 간 간격을 확보했다.
- 1000×720 및 900×640에서 한 화면에 보이는 행 수가 급격히 줄지 않도록 내부
  스크롤 계약과 함께 Tauri E2E에서 행 높이·카드 간격을 검증한다.

### 2026-08-06 가져오기·타이포그래피 가독성 보정

- 현장 배부 호 제목의 숫자와 `년·월·호` 접미사 사이를 고정 슬롯·명시적 간격으로
  정리해 글자 폭에 따라 자간이 흔들리거나 세로로 쪼개지지 않게 했다.
- 신청자 상세의 구독 이력 카드에서 시작·끝 호, 수량, 상태를 전용 열로 정렬해
  수량이 두 기간 행의 중앙에 안정적으로 보이게 했다.
- 갱신 시작 연도·수량의 보이는 추천 목록을 제거하고 직접 입력만 남겼다.
- Google 응답 붙여넣기 설명을 두 줄로 나누고, 바로 추가·확인 필요·오류 요약과
  수동 열 매핑을 읽기 쉬운 격자로 재배치했다. 응답 행 입력란의 Tab 삽입과
  텍스트 입력 중 전역 되돌리기 단축키 보호를 추가했다.
- 정보 툴팁의 폭 계산을 고정해 긴 문장이 한 글자씩 세로로 렌더링되지 않게 하고,
  통계 4칸에는 라벨·수치 위아래 여백을 확보했다.

이 변경으로 2026-08-05에 기록된 갱신 입력 추천 목록 결정은 대체되었으며, 현재는
시작 연도·수량 모두 직접 입력만 지원한다.

### 2026-08-06 관리 화면 구분·초기 창·메모 보관함 보정

- Google 응답 가져오기에서 입금 제외 안내를 요약과 행 목록 사이의 저채도 보조
  박스로 분리하고, 구독 이력의 수량과 현재 상태를 같은 기준선에 중앙 정렬했다.
- 신청자 관리 목록을 검색·보관 토글·집계·인원 목록 영역으로 저채도 배경과 얇은
  선으로 구분하고, `정보 보완 필요` 집계를 누르면 해당 이름만 필터링하도록 했다.
- 상단 관리 버튼은 일반체로 통일하고 초기 창을 1120×760으로 조정했다. 최소
  900×640과 내부 스크롤 계약은 유지한다.
- 메모 보관함의 숫자 배지는 활성 메모 수와 혼동될 수 있어 제거하고 보관함 진입
  텍스트만 남겼다.

### Phase 5 — 배포 준비 (2026-07-27, 대부분 완료)

- 개인정보 비포함 회전 로그, 도움말의 앱·데이터·로그 경로, 담당자 안내서,
  릴리스 체크리스트와 macOS·Windows 패키징 워크플로를 추가했다.
- Apple Silicon 및 Universal macOS DMG, Windows x64 NSIS 산출물과 무결성,
  무인 설치 스모크를 검증했다.
- Intel Mac 및 Windows 10/11 실제 장치에서의 미서명 경고를 포함한 사람의
  설치 경험 확인은 진행 중이다.

## 4. 2026년 최초 이전 및 데이터 감사 기록

- 제공된 2026년 월별 XLSX는 원본을 수정하지 않고 익명 fixture와 별도 변환
  절차로 검증했다.
- 두 자리 연도 형식과 식별 정보 누락으로 생긴 시작 호 불일치 및 중복 후보는
  원본 기간·수량·관계가 모두 확인된 대상만 교정했다.
- 확정된 교정은 구독·신청자 관계를 정리하되 배부·취소 이력은 보존했다.
- 원본 기간, 수량, 동일인 여부가 불확실한 항목은 확인할 일로 유지했다.
- 이 과정에서 실제 운영 데이터와 개인정보는 저장소·fixture·로그에 복사하지
  않는 원칙을 적용했다.

## 5. 전체 변경 이력

### 2026-08-07

- 현장 배부 검색창에서 `ArrowDown`으로 첫 신청자 행에 진입하고 `ArrowUp`·
  `ArrowDown`으로 선택·포커스를 한 명씩 이동하도록 정비했다. 선택 행의 `Enter`는
  배부 확인창을 열며 확인창의 두 번째 `Enter`가 배부를 확정한다.
- 현장 배부의 `ArrowRight`는 우측 메모 입력으로 이동하고, 메모 입력의 일반
  `Enter`는 저장하며 `Shift+Enter`는 줄바꿈을 삽입하도록 했다. 신청자 관리도
  검색창 방향키 진입과 목록 이동 때 오른쪽 상세 갱신을 지원한다.
- 읽기 전용 키보드 이동은 개인정보를 포함한 업무 로그를 추가하지 않고, 기존
  배부·메모 변경 경로의 로그와 되돌리기 기록을 그대로 사용한다.
- 키보드 탐색·배부 확인·메모 입력·신청자 상세 갱신에 단위·통합·Tauri E2E
  검증을 추가하고 문서의 요구사항·검증 목록을 갱신했다.
- 배부 첫 행의 위 방향키와 메모 입력의 왼쪽 방향키가 검색창·선택 행으로
  돌아가도록 포커스 경계를 보완했다. 확인창을 Escape로 닫은 뒤 Enter로 다시
  열 수 있도록 선택 행 포커스를 복원했다.
- 신청자 관리 상세에 이력 없는 잘못된 등록을 위한 확인 후 영구 삭제를 추가하고,
  구독·배부·개별 구매·메모 이력이 있으면 삭제를 차단하고 보관을 안내한다.
  시작·성공·실패 이벤트는 개인정보 없이 운영 로그에 남긴다.
- 현장 간이 등록의 ISO 신청 시각을 서울 지역의 읽기 쉬운 날짜·시각으로 표시했다.
- 배부 검색·표 제목 주변의 인접한 중복 구분선을 하나로 정리하고, 동일한 4칸
  통계의 내부 좌우 여백과 일부 배부 수량 입력의 라벨·입력 간격을 보정했다.
- macOS Command와 Windows Ctrl의 `1`·`2` 화면 전환을 입력 포커스에서도 제공하고
  단위·통합·Tauri E2E 회귀 검증을 추가했다.
- 닫힌 필터 버튼의 `남은 배부 · 2`·`전체 · 4` 표기가 신청자 수로 오해될 수 있어
  선택 개수만 보여 주는 `필터 · N개`로 통일했다. 빠른 선택 이름은 열린 메뉴에서만
  제공한다.

  입력의 시작 연도·매 호 수량에 추천 목록과 직접 입력을 함께 제공하도록 정했다.

  요구사항과 업무 변경 이력에 반영했다.

### 2026-08-05

- 현장 배부와 신청자 관리의 타이포그래피를 역할별 토큰으로 정리했다. 실제 본문과
  신청자 이름은 15px, 표 머리글·짧은 라벨·보조 본문은 14px, 날짜·출처·연결 대상
  같은 메타정보는 13px로 키웠고 검색창의 `/` 키힌트만 12px로 유지했다. 고정 창과
  내부 스크롤 계약은 유지하며 1000×720·900×640 레이아웃으로 검증한다.

- 현장 간이 등록은 이름을 필수로 하고 또래는 선택 입력으로 유지했다. 또래 입력은
  두 자리 숫자만 허용하며, 일반 활성 신청자의 또래 누락은 `정보 보완 필요`로
  분류하지 않도록 기준을 되돌렸다. 입력 오류는 필드 인라인 안내와 일시적 오류
  표시로 제공하고 공통 타이포그래피를 한 단계 키우기로 했다. 단체 신청자가
  드물다는 운영 판단에 따라 개인·단체 유형을 별도 데이터 모델로 추가하지 않았다.

- 신청자 상세의 배부 이력은 가져온 기록의 동일한 처리 시각에 의존하지 않고
  최신 QT 호, 처리 시각, 수정 시각, 내부 ID 순으로 결정적으로 정렬한다. 메모
  보관함은 다른 대화상자와 같은 `Escape` 닫기 동작을 제공한다.

- 단문 메모 상세 창의 과도한 빈 공간을 줄이면서 여러 줄 편집 영역은 충분히
