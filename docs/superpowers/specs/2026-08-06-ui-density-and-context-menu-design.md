# UI 밀도·우클릭 메뉴 개선 설계

## 목표

현장 배부와 신청자 관리에서 본문 가독성은 유지하면서, 배부 버튼·보조 버튼·상단 정보가 과하게 굵고 붙어 보이는 문제를 줄인다. 이름과 구독 기간을 찾는 현장 흐름은 단순하게 만들고, 신청자 행의 우클릭 작업은 실제 포인터 위치에서 바로 사용할 수 있게 한다.

## 합의된 범위

- 현장 배부 검색은 이름·이름 일부·또래·또래+이름만 지원한다. 전화번호는 현장 배부 검색어와 도움말에서 제외하고 신청자 관리 검색·상세·수정 화면 접근성은 유지한다.
- 본문과 신청자 이름은 15px을 유지한다. 호 제목·통계·버튼만 역할에 맞게 한 단계 낮추고 버튼의 높이·좌우 여백·최소 너비를 늘린다.
- `+ 현장 간이 등록`은 보조 버튼 굵기로 표시한다. 배부 버튼은 긴 수량도 한 줄에 읽히도록 고정 최소 너비를 갖는다.
- 점 세 개 메뉴는 기존 행 앵커를 유지한다. 행 우클릭은 같은 항목을 화면 가장자리에서 보정된 포인터 기준 팝오버로 제공한다. 팝오버는 한 번에 하나만 열리고 바깥 클릭·Escape로 닫힌다.
- 구독 이력 카드는 시작·끝 호와 상태 사이의 고정 영역에 `N권`을 표시한다.
- (대체됨 2026-08-06) 구독 시작 연도와 매 호 수량은 추천값을 보여주는 datalist와 직접 입력을 함께 제공한다. 현재 제품 기준은 목록 없이 직접 입력만 제공한다.
- Google 응답 붙여넣기 대화상자는 현재보다 좁게 줄이되 긴 행은 내부 줄바꿈·스크롤로 보존한다.
- 데이터 백업·복원의 내보내기·가져오기는 같은 크기·굵기·우선순위로 맞춘다. 색상은 의미를 위해 다르게 둘 수 있다.
- 내부 툴팁은 내용에 맞춰 자동 높이를 사용하고 최대 너비·줄바꿈·뷰포트 경계를 적용한다. 도움말의 전화번호·구독 설명은 bullet 목록으로 정리한다.
- 제품 화면의 우클릭에서 WebView의 `Reload`는 노출하지 않는다. 입력 컨트롤에서는 운영체제의 복사·붙여넣기 메뉴를 방해하지 않는다.

## 구현 경계

- 도메인 검색 규칙은 현장 배부용 검색 포트와 신청자 관리 검색 포트를 혼동하지 않도록 UI 요청에서 범위를 제한한다. 전화번호 정규화 도메인 로직과 관리 화면 검색은 보존한다.
- 우클릭 메뉴 위치·뷰포트 보정은 UI 어댑터에 두고, 메뉴 작업 자체는 기존 애플리케이션 명령을 사용한다.
- CSS 토큰은 본문/보조/메타와 조작 요소의 역할을 분리한다. 창은 1120×760으로 시작하고 900×640을 최소로 하며, 전체 스크롤 없이 내부 영역만 스크롤한다.

## 검증

- 이름·또래 검색과 전화번호 현장 검색 미지원 회귀 테스트
- 배부 버튼의 최소 너비·긴 수량 라벨·보조 버튼 굵기 테스트
- 우클릭 메뉴의 포인터 위치, 뷰포트 보정, Escape·바깥 클릭, 단일 팝오버 테스트
- 구독 카드의 시작·끝·수량·상태 배치 테스트
- 시작 연도·수량 직접 입력과 동일 높이 테스트
- 붙여넣기·백업 대화상자 폭과 동등 버튼 스타일 테스트
- 툴팁 뷰포트 내 배치와 도움말 bullet 콘텐츠 테스트
- 기존 단위·통합·E2E 및 `just check` 실행
