# 0.2.1 현장 화면 보정 Implementation Plan

**Goal:** 사용자가 0.2.0에서 확인한 입력·선택·단축키·정정·도움말 배치를 수정한다.
**Architecture:** 기존 React 컴포넌트와 테마를 재사용한다. 저장 형식과 업무 원장은 변경하지 않는다. 정정에서 숨긴 신청일·메모는 원래 값으로 전송해 보존한다.
**Tech Stack:** React/TypeScript, Rust/Tauri, Vitest, WebdriverIO, just.
**Spec:** PROJECT_SPEC.md FR-OPS-003/005/006/007/008, FR-DIST-010/015, FR-SUB-028, FR-SALE-002, FR-HELP-009/011/014.

## 제약과 점검

- 현재 승인된 작업 폴더에서 직접 진행한다. 에이전트·worktree·Git 쓰기·HTTP 작업은 자동으로 추가하지 않는다.
- 버전은 0.2.1, SQLite v7·XLSX v4 유지. 운영 데이터와 이전 0.2.0 산출물을 수정하지 않는다.
- 또래 예외를 선택하면 입력값을 지우고 비활성화하며, 해제 후 빈 값으로 시작한다. 저장상 예외와 누락은 계속 구분한다.
- Enter는 선택된 만료 행의 구독 추가를 열고 조합 중·키 반복·팝업 안의 입력을 가로채지 않는다.
- 기존인 선택과 해제는 같은 높이의 입력 슬롯을 쓰며 필수 입력값·포커스·후보 선택을 보존한다.
- 900×640에서 도움말 제목·모드·검색이 겹치지 않고 본문만 스크롤한다.
- 숨긴 신청일·메모는 null이나 빈 값으로 덮어쓰지 않도록 요청과 저장 결과를 검사한다.

- 집중 회귀 검사의 실패를 확인한 뒤 구현했다. 프론트엔드 164개와 Rust 120개, Python 2개를 포함한 `just check`가 통과했다.
