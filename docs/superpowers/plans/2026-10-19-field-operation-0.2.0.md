# 현장 운영 개선 0.2.0 작업 계획

작성일: 2026-10-19. 상태: 사용자 결정·작업 순서 승인 반영, 전체 테스트 감사 추가. 구현 시작 전.

**Goal:** 현장 배부에서 전체 신청자를 빠르게 검색하고 구독 추가·배부·이력 정정까지 처리하며 Windows 사용 문제와 구버전 기능 잔재를 정리한다.

**Architecture:** 기존 도메인 → 애플리케이션 → UI/SQLite/XLSX 어댑터의 의존성을 유지한다. 검색과 자격·정정 규칙은 도메인/애플리케이션에서 정의하고 UI는 선택과 확인을 담당한다. 실제 사용 데이터의 기존 이력을 유지하며 저장 형식 변화는 마이그레이션과 백업 왕복 검증을 동반한다.

**Tech Stack:** React/TypeScript, Rust, Tauri 2, SQLite, XLSX, Vitest, WebdriverIO, just.

**Spec:** `PROJECT_SPEC.md`를 기준으로 아래 확정 사항을 구현 시 함께 갱신한다. 관련 기존 요구사항: FR-DIST-019/023/027/037, FR-SUB-003/005/014/028, FR-KEY-007/009 및 검색·도움말·백업·배포 절.

**Execution:** 승인 후 현재 작업 환경에서 순서대로 진행한다. 에이전트를 자동 추가하지 않는다. 각 단위는 실패 재현 또는 수용 테스트 → 최소 구현 → 관련 검증 → 문서·업무 이력 반영 순서로 수행한다.

**Test audit:** 새 기능 관련 검사뿐 아니라 기존 전체 테스트의 검증 대상·현실성·누락을 먼저 감사한다. 발견한 부족분을 각 작업과 함께 보강하고 릴리스 전에 전체 감사 항목을 다시 대조한다.

## 확정한 동작

- 현장 배부 기본 필터는 전체다. 미배부·일부 배부·배부 완료·구독 만료·구독 예정·구독 없음의 6가지 상태를 포함한다. 보관된 신청자는 신청자 관리에서 조회한다.
- 검색은 선택한 필터를 그대로 따른다. 필터 밖 결과를 별도로 보여주거나 탭 전환마다 검색어를 강제로 복사하지 않는다. `남은 배부` 빠른 선택은 미배부·일부 배부로 유지한다.
- 노란 메모 점은 활성 연결 메모만 참조한다. 메모 삭제·보관·복원 후 모든 관련 화면에 즉시 반영한다.
- 등록·수정 화면의 또래에 `해당 없음` 체크를 제공한다. 미입력과 해당 없음을 구분하고 후자는 누락 경고에서 제외한다. 이름에 ‘셀’이 있는지로 추정하지 않는다. 해당 없음은 군지체의 특수 배부 방식과 독립적이다.
- Windows 메뉴는 한 줄로 표시하고 일반 설치 앱은 터미널 창 없이 실행한다.
- 조합 중 한글(초성·미완성 모음·받침)을 포함한 이름 검색을 현장 배부·신청자 관리·입금 관리·사람 선택창에 적용한다. 정확한 이름 일치를 우선한다.
- `/`는 현재 탭 검색창에 포커스를 주고 기존 내용을 전체 선택한다. 검색창의 `Esc`는 검색어를 비운다. 한글 조합 취소 및 열린 팝업 닫기를 먼저 처리하고 메모·다른 입력은 지우지 않는다.
- 도움말에 `간략 / 자세히`를 제공하고 처음에는 간략으로 연다. 간략은 특별한 기능과 실수하기 쉬운 규칙에 집중한다.
- 1년 구독은 시작 연도·호를 선택하며 기본값은 현재 배부 화면의 호다. 마지막 대상 호를 미리 표시한다.
- 현재 화면과 같은 호부터 시작하는 1년 구독은 `신청 + 배부`가 기본 제출 동작이다. 다른 호부터 시작하면 `신청만 저장`이 기본이며 현재 호에 잘못 배부하지 않는다.
- 1달 구독은 현재 배부 화면의 호만 구매·즉시 전달한다. 미래 신청과 나중 배부를 위한 새 상태는 만들지 않는다.
- 1년·1달 구독 이력에 작은 연필 아이콘 버튼으로 수정을 제공한다. OS별 모양이 달라지는 이모지 대신 아이콘과 접근성 이름·툴팁을 사용한다.
- 연간 시작 호·권수 수정 시 실제 배부 기록을 유지한다. 수정 전후 기간·권수와 불일치하는 배부를 먼저 보여주고 확인 후 정정한다.
- 1달 구독도 정정할 수 있다. 원본과 정정 이력을 유지하고 유효한 정정 결과를 구매·전달 합계와 입금 화면에 한 번만 반영한다.
- 이번 앱 버전은 0.2.0이다. 이후 코드 변경 작업 묶음마다 버전을 갱신한다. 기능 추가는 minor, 오류 수정은 patch를 기본으로 하고 패키지·Cargo·앱 정보·릴리스 문서를 일치시킨다.

## 공통 제약

- 실제 운영 데이터·원본 XLSX·개인정보 로그·운영 데이터 복제 fixture를 Git에 추가하지 않는다. 현재 운영 데이터의 복사본은 승인된 로컬 경로에서만 다룬다.
- 구버전 기능의 불필요한 실행 경로를 제거하되 이전 설치 데이터와 백업을 안전하게 읽는 변환 경로를 먼저 검증한다. 과거 마이그레이션을 단순 삭제하지 않는다.
- 필요한 저장 변경은 하나의 호환성 계약으로 묶는다. 기존 SQLite v6와 XLSX v3을 새 앱에서 읽고 새 형식으로 다시 내보내는 검사를 포함한다. 새 형식은 구버전 앱에서 사용하지 않도록 안내한다.
- 기존 실제 배부를 구독 수정에 맞춰 자동 재작성하지 않는다. 변경 전후·담당자·시각과 고정 업무 요약을 기록하며 운영 로그에 이름·연락처를 출력하지 않는다.
- 한글 조합 중 Enter·누르고 있는 Enter·빠른 연속 클릭으로 중복 등록·배부되지 않아야 한다.
- GitHub HTTP 작업은 사용자가 터미널에서 실행한다. Windows 결과를 macOS 테스트로 대신하지 않는다.

## 0. 기존 전체 테스트 감사와 보강 목록 작성

범위: `src/**/*.test.*`, Rust 각 크레이트의 단위·통합 테스트, `tests/e2e`, fixture와 테스트 보조 함수, `justfile`, CI·패키지 검증. 이번 11개 피드백 외의 기존 핵심 업무도 포함한다.

- [ ] 요구사항·핵심 사용자 흐름별로 현재 테스트, 검증 수준, 빠진 조건, 보강할 계층을 대응한 감사표를 만든다. 정적 마크업·동작·실제 OS 검사를 구분하고 테스트 개수나 단순 줄 커버리지로 충분성을 판단하지 않는다.
- [ ] 현재 로컬 검증 결과와 제외·미실행 항목을 기준선으로 기록한다. 실패가 있으면 기존 실패인지 새 변경 때문인지 식별하고 실제 실행하지 않은 OS를 통과로 표시하지 않는다.
- [ ] UI 테스트가 글씨·속성·마크업 존재만 검사하면서 클릭·폼 제출·포커스·상태 변경까지 검증한 것처럼 취급되는 부분을 점검한다. 실제 앱의 컨트롤 조작과 저장 결과 검사를 보강하며, 임시 DOM의 클릭 검사만으로 실제 필터 동작을 대신하지 않는다.
- [ ] E2E의 DOM `.click()`·직접 이벤트 발생·백엔드 명령 호출이 사용자 입력 경로를 우회하는 지점을 분류한다. 입력 버그에 중요한 경로는 실제 포인터·키보드 조작으로 검증하고, 백엔드 fixture 작성은 준비 단계에만 사용한다.
- [ ] 한글 IME·키보드·일반 클릭·라벨 클릭·연속 입력, 빈값·경곗값·취소·저장 실패·오래된 비동기 응답·앱 재실행 등 실패하기 쉬운 조건의 누락을 확인한다. 불필요한 대기·재시도나 약한 단언으로 실패를 숨기지 않는다.
- [ ] 도메인·애플리케이션·SQLite·XLSX·Tauri 연결 사이에 같은 규칙이 다르게 적용되거나 mock만 통과하는 구간을 찾는다. 도메인 계산은 빠른 단위 테스트, 트랜잭션·마이그레이션·백업은 실제 임시 저장소, 사용자 조작은 UI/E2E에서 검증한다.
- [ ] 기존 구독·여러 권·부분 배부·취소/되돌리기·군지체·입금·메모·중복 등록·붙여넣기·백업 병합/교체/복원·도움말·설정 유지의 보호 여부를 점검한다. 합계와 상세 이력, 배부 자격, 변경 이력이 서로 일치하는지 확인한다.
- [ ] 제외된 테스트와 구버전 기능 테스트를 검토해 현재 흐름의 보호를 새 테스트로 옮긴 뒤 중복·폐기 테스트를 정리한다. 제외 사유와 대체 검증이 없는 핵심 경로는 보강 대상으로 남긴다.
- [ ] 실제 운영 개인정보를 사용하지 않는 독립 fixture인지, 다른 테스트의 실행 순서·공유 상태·타이밍에 의존하는지 확인한다. 익명 자료로 필요한 경계·오류 조건을 만든다.
- [ ] 부족분은 데이터 손실·오배부·중복 저장·잘못된 합계·사용 불가 위험을 우선해 아래 각 작업에 배정한다. 단순 구현 복제 테스트나 의미 없는 중복 검사는 추가하지 않는다.

감사표의 필수 열: 요구사항/흐름, 현재 증거와 검증 계층, 누락·문제, 보강 작업, 새 검증 결과, 실제 OS 결과 또는 미실행 사유. 개인정보가 없는 요약을 릴리스 체크리스트에 남긴다.

## 1. 현장 필터와 메모 표시, 구버전 기능 감사

주요 대상: `src/PersonFilterMenu.tsx`, `src/distributionView.ts`, `src/App.tsx`, `crates/qt-application/src/phase2.rs`, `crates/qt-infrastructure/src/sqlite_distribution_desk.rs`, 관련 테스트.

- [ ] 기본값과 `남은 배부` 프리셋 상수를 분리해 기본 전체 전환으로 프리셋의 의미가 바뀌지 않게 한다.
- [ ] 예정·구독 없음도 응답과 목록에 포함하고 필터별로 선택 가능하게 한다. 상단 배부 대상·완료·남음 통계는 실제 현재 호 자격 기준을 유지한다.

- [ ] 메모 점의 `check_items` 참조를 제거하고 표시·배부 전 확인·상세 목록이 같은 활성 메모 기준을 사용하도록 한다.
- [ ] 구버전 확인할 일·고정 메모·신청자 단일 메모의 UI/API/업무 서비스/저장소/백업/테스트 참조를 전체 검색해 의존성을 분류한다. 사용하지 않는 공개 경로와 중복 분기를 제거한다.
- [ ] 구버전 자료를 메모로 변환하는 경로의 누락·중복 여부를 검사한다. 유지해야 할 호환 코드에는 실제 읽는 형식과 존속 이유를 적는다. 감사 결과를 역사 문서에 남긴다.

검증: 기본 전체·6개 필터 조합·검색과 필터 일치·원래 통계 불변, 활성 메모 0/1/여러 개 및 마지막 메모 보관·삭제·복원, 구버전 자료 변환과 재가져오기.

- [ ] 이름·또래 조합, 공백 무시, 선행 0, 기존 전화번호 검색의 화면별 범위를 유지한다. 정확 일치와 기존 현장 우선 정렬 기준을 함께 정의한다.

검증: 익명 이름의 초성/중간 입력/복합 모음/받침 추가 과정, 부분 문자열·또래 혼합, 1,000명 검색 반응, 각 탭과 선택창 결과 일치, 조합 중 Esc·Enter와 일반 입력 보호.

## 4. 구독 이력의 연필 수정과 정정 기록

주요 대상: `src/ManagementDetail.tsx`, 책임별 수정 대화상자·검증 모듈, `src/phase3.ts`, 구독/구매 정정용 애플리케이션 서비스·저장소, Tauri 명령, 상태 백업·병합.

- [ ] 이력 행에 작은 연필 버튼을 제공하고 키보드 포커스·접근성 이름·툴팁을 넣는다. 행 상태와 수정 대상을 ID로 정확히 연결한다.
- [ ] 연간 시작 호·권수·신청일·메모의 수정 전후 값을 검증한다. 기간 밖 배부와 변경 권수 초과 배부를 미리보기로 보여주고, 확인은 현재 값에 대한 검증 결과와 함께 저장해 경합을 막는다.
- [ ] 연간 정정은 실제 배부 행을 유지한다. 배부 초과·기간 불일치를 화면과 내보내기에서 식별 가능하게 하고 추가 배부 가능 권수는 음수가 되지 않게 한다.
- [ ] 1달 구독은 원본을 남기고 유효한 정정 기록과 연결한다. 기존 취소와 정정이 겹쳐도 합계가 중복·이중 차감되지 않게 한다. 수정 당시의 입금 상태와 신청자 연결을 유지한다.
- [ ] 연간·1달 정정을 원자적으로 저장하고 업무 이력에 변경 전후·담당자·시각을 남긴다. 정정 기록과 연결은 XLSX 왕복·병합·복원에서도 유지한다.

검증: 배부 없는 수정, 배부와 일치/불일치 수정·확인 취소, 중첩 구독, 취소된 구매와 여러 차례 정정, 입금 확인 전후 수정, 정정 후 재실행·집계·백업 왕복.

## 5. 연간 시작 호 선택과 신청 + 배부

주요 대상: `src/AnnualSubscriptionForm.tsx`, `annualRegistration.ts`, `Phase2Dialogs.tsx`, `Phase3Dialogs.tsx`, 연간 등록·갱신 서비스 및 배부 서비스.

- [ ] 연간 구독 창에 시작 연도·호와 마지막 호 미리보기를 추가하고 선택한 호로 중복 기간 경고를 계산한다. 기본은 현재 배부 화면의 호다.
- [ ] 같은 호 시작은 `신청 + 배부`를 기본 제출로, 다른 호 시작은 `신청만 저장`을 기본 제출로 둔다. 신규·기존 인원 모두 동일하다.
- [ ] 신청 + 배부의 대상·권수를 확인 가능하게 한다. 활성 메모가 있으면 기존 배부 전 메모 확인을 통합한다. 이번에 추가하는 구독의 권수와 기존 미배부 권수를 혼동하지 않게 한다.
- [ ] 신청과 배부를 원자적으로 완료하거나 실패 상태를 명시해 재시도로 중복 구독이 생기지 않도록 한다. Enter 연속 진행은 허용하되 조합 확정 Enter·키 반복은 제출하지 않는다.
- [ ] 메모 최종 확인 전에는 신청·배부를 저장하지 않는다. 확인 취소는 둘 다 미저장, 저장 실패는 둘 다 롤백한다. 완료 후 배부 되돌리기는 실제 배부만 취소하고 구독은 유지하며, 안내 문구에 그 결과를 명시한다. 신청만 저장은 배부 성공으로 안내하지 않는다.
- [ ] 1달 구독은 현재 화면 호의 즉시 구매·전달 동작을 유지하고 시작 호 선택·신청만 저장을 추가하지 않는다.

검증: 신규·기존 신청자의 당월 신청 + 배부, 여러 권·여러 구독, 다음 해 시작·6개 호 계산, 미래 시작 신청만 저장, 겹침 확인, 메모 확인·취소, Enter·클릭 연속 입력과 원자성·되돌리기.
